2026-11-28 に形式検証の使い分けを再確認した。`create-formal-verification-skill` は対象と性質を選んで検査を作り、`maintain-formal-verification-skill` は実装変更後にモデルや前提のずれを調べる。`statechart` は TLA+ を検査し、到達状態や違反経路を図にする。dotagents は作成・保守を `da-write-checks` で受け、設計中の反例は `da-review` で調べる。[pstack の使い分け](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/06-verify-and-ship.md)・[dotagents の選定基準](../skills/da-write-checks/reference/formal-methods.md)

検証を実際に動かし、失敗できることを確かめ、手順を次の実行者へ残す考え方を取り入れる。既存の TDD・検証ゲート・実装ループと同じ役割のものは重ねない。上流版をそのまま選択導入し、本文の翻訳・改変・vendoring は行わない。

## 使うコマンド

Claude Code・Cursor は `/why`、Codex は `$why` のように呼ぶ。選択導入は `-a claude-code -a cursor` を指定し、共有実体とClaude Code用リンクを両方配置した。全7本とも上流の `disable-model-invocation: true` を維持する。自動適用や、別のスキルからの `Skill` 呼び出しを保証する構成ではない。使う段階と、上流・dotagents・プロジェクトの責務は [README](../README.md#用途に応じて入れるもの) にまとめた。

| 名前 | 補う不足 | 既存との使い分け |
|---|---|---|
| `why` | 判断の来歴をコミットとPR議論から再構成する | 動作や依存経路を追う `da-investigate` と問いが違う |
| `sharpen` | 範囲を増やさず、原資料・方法・判定を含む依頼へ直す | 要件を質問で詰める `grilling` の前に、依頼文そのものを作る |
| `correct` | 繰り返す失敗を、構造・型・lint・テストで防ぐ | セッションを振り返る `retro` と異なり、過去の反復を調べて実装とコミットまで進める |
| `benchmark-checklist` | 数字を信じる前に処理実行・エラー・限界・反復を確かめる | 一般の成功／失敗の検証に、性能測定固有の点検を足す |
| `create-verification-skill` | 実アプリを起動・操作して確かめる手順と機能マップを作る | `da-verify` の既存コマンドの実行を、操作手段の生成まで補う |
| `maintain-verification-skill` | 機能マップと現在の実装・実操作を照合する | 検査の成功だけでは分からない、手順の陳腐化を扱う |
| `statechart` | TLA+の検査結果を、状態図と違反への最短経路にする | Archify はコードや要求を図にする。こちらはモデル検査の結果を描く |

### 依頼例

```text
$why hooksをシンボリックリンクではなくコピーにした判断を、コミットとPR議論から説明して。確認できた理由と推論を分けて。

$sharpen 「この画面を速くしたい」を、元データ・計測方法・成功判定が明確な依頼へ直して。機能の範囲は増やさないで。

$correct このリポジトリで2回以上起きたミスを、構造・型・lint・テストの順で防いで。AGENTS.mdのTDD・モデル継承・検証規約を優先して。

$create-verification-skill このアプリの実操作を検証する手順を作って。生成物は日本語で、配置はこのプロジェクトで3ツールが共有する既存の配置に従って。既存配置がなければ .agents/skills/ を使って。起動から証拠保存・後片付けまで実行して。

$maintain-verification-skill 対象は .agents/skills/verify-app/。製品の回帰と手順の古さを分け、実操作でも確認して。

$statechart この受付とキャンセルの遷移を小さいモデルで調べて。利用者が合意する不変条件と探索範囲を明記し、反例は実装でも再現して。
```

検証生成の上流既定は `.cursor/skills/`。共有先を指定せずに生成したスキルが、Claude Code・Codex でも見つかるとは主張しない。生成先・日本語・既存profile・権限は、対象プロジェクトとユーザーの規約を優先する。生成・保守をインストールしただけでは、プロジェクトの検証手順はまだ作られない。

`benchmark-checklist` の `nproc` が無いmacOSでは、CPU数を `getconf _NPROCESSORS_ONLN` で確認できる。計測対象が処理を実行したかとエラー数の点検は、短い概算でも省略しない。比較の優劣を示す時は反復と実利用の経路まで確かめる。

## 今回は入れないもの

| 対象 | 理由 |
|---|---|
| `poteto-mode`、`setup-pstack` と大きなオーケストレーション一式 | 既存の駆動系と入口が重なり、常設の役割別モデル設定や多くのプレイブックを持ち込む。セッションのモデルを継承する規約を維持する |
| `tdd` | 高価・不明瞭なテスト経路では省略する方針があり、常に失敗するテストから始める既定と異なる |
| `how`、`teach`、`blast-radius` | 調査・説明・レビューの既存入口と重なり、別スキルの呼び出しや複数役の依存も増える。未確認の安全前提を実行で確かめる観点は既存の証拠規律で使う |
| `arena`、`swarm`、`interrogate`、`reflect` | 既存のレビュー・並列数の判断と重なる。数や別モデルを増やすこと自体を改善としない |
| `no-comments` | コメントを剥がす入口は、実際の失敗や判断理由をコメントへ残すこの構成と合わない |
| `create-formal-verification-skill`、`maintain-formal-verification-skill` | 候補として監査したが、まだ保守対象のプロジェクト用モデルがない。まず直接実行できる `statechart` を使い、実装との対応・再検証の保守が必要になった時に再考する |
| その他の文体・説明・履歴・個人モードの補助と原則スキル | 既存の文章規約・図解・振り返り・状態からの引き継ぎで足りる。原則を呼び出すだけの入口を一式追加しない |

「入れない」は各スキルの一般的な品質の評価ではなく、この構成へ今足す必要性の判断である。採用しない全本文を逐語レビューしたとは主張しない。

### 実行コードの境界

`statechart` はNode 24で動作し、初回にmiseでTLC 1.7.4とJava Temurin 25を取得する。TLCの取得先は固定URLとSHA-256が指定されている。今回取得されたJavaは `temurin-25.0.5+8.0.LTS` で、既定のJavaには設定されていない。`mise use` やモデルを固定する設定は行っていない。

`--view` は通常のJavaScriptとして実行され、環境変数も継承する。作業用ディレクトリへ分離することはOSのsandboxではない。自分が書いたか、内容を確認したspec・config・viewを使う。新規または空の出力先を指定する。実装を表すモデルの反例は、その実装へ戻して再現する。

画像を描く場合の上流の手順はPele 1.9.0を使う。今回はMermaidテキストと検査結果までを確認し、画像用のPeleは導入していない。上流の `npm test` は描画用npm依存を別途取得するため、小さいTLC動作確認とは分けた。`STATECHART_UPDATE` を有効にしたfixture更新も実行していない。

## 予算と保守

導入前はディスク上で39本、リンターのdescription計測は6,286字。候補9本を入れた時点で48本・8,742字となり、8,000字の目安を超えた。形式検証の生成・保守2本はCLIのリンク解除に加えて共有ディレクトリの残った実体も除去し、最終的に46本・7,916字とした。既存の39本は削除も編集もしていない。

46本は40本という本数の目安を超える。追加7本を明示呼び出しとして整理したが、メニューの負担が消えるとは言わない。この数値はファイル監査の計測であり、組み込み・プラグインを含む全コンテキストの実測ではない。次の追加では重複と実利用を再点検する。

インストール済み全体へのlintは導入前17エラー・44警告、導入後17エラー・56警告。既存の危険例・独自URI等を検知するエラーは残り、全体がlint成功したとは報告しない。上流の本文をローカルの必須節へ書き換えたり、許可リストで黙らせたりしていない。

追加前後のエラー集合が同一であること、Claudeと共有ディレクトリの名前一覧が一致することを確認した。dotagents自身の `gate.sh verify --json` は終了0、`ok: true`、該当する4チェックが成功した。対象外の検査は `skipped` に記録され、全スイートを実行したという意味ではない。

インストールは `skills@1.7.4` と固定コミットURLを使い、`-s` で7本を指定した。Claude Codeのリンクと、Cursor・Codexが読む共有実体を配置した。Claude CodeはCLIでの登録を確認したが、モデル実行は認証で失敗した。Cursor・Codexの実アプリ内での操作と、スキル同士の自動連鎖は未検証。導入後の次のターン以降に一覧が更新される。
