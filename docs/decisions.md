# 判断の記録

ADR 7本を1本に畳んだもの。**現在有効な判断**と、**間違えて反転させた判断**だけを残しています。畳んだ理由は、0003 を 0005 が修正し、0004 を 0006 が部分反転し、0005 の一部を 0006 が範囲縮小していて、**1つの判断の現状を知るのに4本読む必要があった**こと。

各項目は「何を決めたか / なぜ / 代償」で書きます。代償の欄が空のものは、代償を測っていないという意味です。

---

## 1. 配布はグローバル1箇所、`~/.agents/skills/`

**プロダクトリポジトリには1ファイルも置きません。** これが全体を規定している制約で、他の選択肢を全部消しています。だから配布はグローバル一本になり、Claude Code へは symlink を張ります。

**Cursor は `~/.agents/skills/` をネイティブに読みます**（実機確認済み）。`~/.cursor/skills/` へのリンクは作りません —— 作っても二重登録はされませんが、買えるものが何も無い。

**代償**: リポジトリ固有のスキルが書けません。プロダクトリポに置けないので、全部グローバルに載るか、載らないかのどちらか。

## 2. hook は symlink ではなくコピーして配る

symlink が切れると hook は `exit 127` を返し、**Claude Code はそれを non-blocking として扱います** —— ガードレールが「止まる」のではなく**「開く」**。コピーは切れません。

具体的な壊れ方: dotagents の checkout を hook が無いブランチに置く、あるいは移動する。それだけで全 hook 呼び出しが 127 を返し、**セッションは正常に見えたまま**ガードレールが効かなくなります。

**代償**: hook を編集しても `setup.sh install` を再実行するまで反映されません。`setup.sh doctor` が「インストール済みのコピーが元と違う」と報告します。

## 3. 挙動は本文に書く。frontmatter はその上の最適化

**Cursor が読む frontmatter は `name` / `description` / `paths` / `disable-model-invocation` / `metadata` だけ**で、それ以外は拒否ではなく**黙って無視**されます。

だから規則はこう: **Claude 専用フィールドを全部剥がしても、スキルは同じ挙動をしなければならない。** 制約は本文に散文で書き、frontmatter は上乗せの最適化として扱います。

`allowed-tools` を「読み取り専用の保証」として使えないのはこれが理由です。Cursor では無視されるので、読み取り専用は**本文の太字宣言**で担保しています。

## 4. `disable-model-invocation` の禁止は「名指し委譲の対象のみ」

当初は全面禁止にしていましたが、**範囲を絞りました**。このフィールドはモデルの自動発火だけでなく**プログラムからの `Skill` 呼び出しと subagent へのプリロードも止めます**。つまり:

| スキル | DMI | 理由 |
|---|---|---|
| `da-pr-describe` | **付ける** | GitHub に書き込むので、タイミングはあなたのもの。description が context から完全に消えるので予算コストもゼロ |
| `da-verify` | **絶対に付けない** | ゲートを arm する唯一のもの |
| `x-review-{backend,frontend,infra}` | **絶対に付けない** | `da-review-all` が**名前で**委譲する。付けるとディスパッチが**無音の no-op** になり、「層はレビュー済み」と報告して何もレビューしない |

lint hook とリンタの両方がテスト付きで強制しています。**リンタ側は一度、`$name` ではなく `$id` を照合していて何も検査していませんでした** —— `$id` は `skills/<name>` なので `case "$id" in verify)` は永遠に一致しない。ガードレールが設置済みで無効という状態だったので、`scripts/test-lint-hook.sh` を書いて回帰を止めています。

## 5. 層別レビューは reference ファイルではなくスキル

一度 reference ファイルに畳んで、3つの劣化を起こして戻しました:

1. 入口が3つ消えた
2. 無音事故パターンが verify フェーズにしか残らず、**find フェーズが読まなくなった**
3. 姿勢が使用箇所から2ホップ離れた

**②③ は誰にも報告されないまま起きていました。** これが「スキルを reference に畳む」ことの本当のコストです。重い観点クラスタは各スキルの `reference/` に残すので、context 経済は保たれます。

## 6. レビューの入口はメニュー上1つだけ

`da-review-all` が唯一のメニュー項目。層別3本は `user-invocable: false` で `/` から消え、**モデルからは呼べるまま**です。「backend をレビューして」と言えば description 一致で層別が直接発火するので、**失うのは「打つ」経路だけ**。

判断 5 を部分的に反転させていますが、**5 が直した不満は「深さの喪失」であって入口の数ではなく、深さは層別スキルに残っています。**

実績は層別 51回 対 `review-all` 6回で層別が主入口でしたが、メニューを小さくする方を選びました。

## 7. 内部用は `da-` ではなく `x-` 接頭辞

`user-invocable: false` は **Claude 専用フィールドで、Cursor は無視します**。さらに **Cursor は subagent もコマンドピッカーに出します**。結果、`/da` が Claude で7件、**Cursor で12件**になっていました —— 差の5本は層別3本＋subagent 2本、どれも打つべきでないもの。

フィールドで隠す方法が両エージェントで成立しないので、**接頭辞を分けました**: `da-` は打つもの（7本）、`x-` は内部（層別3本＋subagent 2本）。どちらのエージェントでも `/da` は7件になります。

**代償**: 名前を変えると3箇所が壊れ、**3つとも無音で壊れます** —— リンタの DMI 検査スコープ、lint hook 内の同じリスト、そして **`` `x-review-<layer>` `` のようなテンプレート内プレースホルダ（名前ベースの一括置換が拾わない）**。実際に2回のリネームで2回とも取り残されました。今はリンタが検査します。

## 8. 抑制は `skillOverrides` で、`setup.sh` の管理下

**面の実数はディスク上の数の3倍以上です。** 過去2回、ファイルシステムを読んだ棚卸しがこれを外しました:

| 出所 | 場所 |

| ディスク上 | `~/.agents/skills/` —— 自作10、残りは上流 |

| **CLI バイナリにコンパイル済み** | **ファイルとして存在しない。ここが最も多い** |

**数字は書きません。** ここは以前「21 / 11 / 40 で計72」と書き、README も同じ数を書き、
`templates/claude.settings.snippet.json` は「24 / 75」と書いていて、**実測は23でした。**
同じ数を3箇所で手で維持すると3つの数になります。`/doctor` と `/skill-doctor` が実数を見ます。

**`disableBundledSkills` は使いません。** バンドル全部がまとめて消えて実績のある `code-review`(42回) / `review`(24回) まで落ちますし、**2.1.219 にしか存在しない**ので `$PATH` の古い `claude` では黙って無効になります。

**レビュー系は意図的に抑制していません。** 4種の AI レビュアを同一146 PR に当てた計測で**指摘の 93.4% は4つのうち1つだけが検出**、4つ全部が検出したものは0件でした。効くのはレビュアの「質」より**「多様性」**です。

## 9. 横断調査は agentic search のまま、ベクトルインデックスは持たない

Milvus×Ollama のローカルベクトル DB を claude-context MCP から引く構成を検討して、採用しませんでした:

1. 上流のメンテが停滞（直近30日で3コミット）
2. **インデックスが絶対パス単位**なので、symlink で作る virtual monorepo は実体パスと別インデックスになり、二重化と鮮度不整合を起こす（公式 FAQ に明記）
3. Milvus Lite 非対応で docker 常駐（etcd＋MinIO＋Milvus）が必須。対価は自己申告の「40%トークン削減」
4. **Claude Code 自身が初期の RAG＋ベクトル DB を agentic search に置き換えています。** 作者が理由に挙げているのは security / privacy / **staleness** / reliability

代わりに virtual monorepo のディレクトリ、`rg` → `ast-grep` → LSP → 通読の段階的探索、`da-investigate` の予算、`x-codebase-explorer` の並列展開で回します。

`codegraph` は**未評価**です。評価していないものを却下したとは書きません。

### 残る露出は3つ

1. **`npx skills` 自体が固定されていません。** これは `vercel-labs/skills`（現 v1.5.20）の npm パッケージで、**このエコシステムからこのマシンで実際に実行される唯一のコード**です（スキル本体はテキストにすぎない）。`npx` は毎回最新を取ってきてファイルシステム権限付きで走ります。**緩和策は `npx skills@1.5.20 add …` のようにバージョンを固定すること。** 現在の README は固定していません

3. **上流11本はこのリポジトリに入っていないので CI が見ていません。** 監査したのは「このマシンの今日の中身」です

だから運用規則は: **`npx skills update` の直後に `skill-scanner` を回す。** 監査は一度で終わりません。

### 管理された例外: 自作スキルの symlink 26本が critical に出る

`scan_skill.py` は **「スキルディレクトリの外に解決する symlink」を critical** に分類します（脅威モデルは `~/.ssh/id_rsa` を参考ファイルに偽装させること）。`_shared/` への26本はこの規則に**真に該当**します。

**これは受容する例外です。** 逃げていないことを実測で確認済み（26本すべて `skills/_shared/` 配下に解決、逸脱0本）。そして `verify-skills.sh` が**リンク先を `../../_shared/<name>` に完全一致で強制**しているので、逸脱は構造的に発生しません。

**この例外を記録している理由は、コピーに戻す「修正」を防ぐためです。** それをやると、下の「`_shared/` は symlink ではなくコピーだった」に書いた4要件と検証者バイアス節が、再びどのレビュースキルにも届かなくなります。**26件の critical は、共有が実際に機能していることの裏返しです。**

# 間違えた判断の記録

残す価値があるのはこちらです。

## 「ゲートは無人運用向けではない」と宣言して、無人運用で壊れる状態機械を放置した

`README.md` には「**深夜に無人で回すためのロックではありません**」と書いてありました。今その立場は
反転しています。ただし**反転したことが学びではありません。** 学びはこちらです:

> **「対象外」と宣言することは、その経路が安全であることの代わりにならない。**
> ゲートは armed 状態を漏らし、上限なくブロックし、記録なく解放していた。そのどれも、README の
> 一文がそのケースを非対応と書いていたことによって許容可能になってはいなかった。

**位置づけはループの話でしたが、欠陥は状態機械の話でした。** 対象外と宣言したかどうかに関係なく、
以下は全部壊れていました:

| 壊れていたもの | 実際に観測されたこと |
|---|---|
| `arm` に期限が無い | 終了済みセッションの armed 状態が残り、5本のチェック（約7秒）を毎ターン走らせていた。trace.log に `passed: all gating checks green` が57回。**disarm は `da-verify` の散文に委ねられていて、散文はセッションの終了を生き延びない** |
| ブロックに上限が無い | `attempts >= 2` はメッセージを強めるだけで、内容は「`/clear` して作り直せ」—— 無人ループが取れない行動 |
| 解放が記録されない | 再入で1回だけ解放する経路が `trace` を呼んでいなかった。「何も起きなかった」と「一度も走らなかった」を区別するために作ったファイルが、**最も頻繁に起きている出来事について沈黙していた** |
| worktree に掛からない | `using-git-worktrees` はこのツールキット自身の推奨する分離手段。trace.log に `.worktrees/…  passed: armed elsewhere` が実在 |
| timeout が無い | ハーネスの timeout で殺された hook は exit 2 にならない = non-blocking。**毎ターン全テストスイートを回す profile が実在する**ので、最も現実的な fail-open 経路だった |

### そこから出た設計判断3つ

- **verdict は「存在しないもの」ではなく「存在するファイル」。** 諦めることが `ACTIVE` を消すだけなら、
  次のセッションの `status` は "not armed" と言う —— **何も arm しなかったセッションと区別がつかず、
  片方だけが「作業は未検証」を意味する。**
- **期限切れは arm からの TTL ではなく idle 基準。** arm からの TTL は可能にしたいものを殺します ——
  6時間の無人実行が飛行中に期限切れして無言で fail-open する。
- **attended / unattended のモードフラグは作らない。** 設定が必要なモードは、まさに必要なときに
  設定されていないモードで、Stop hook から人間が見ているかは確実に判定できません。挙動は一つ:
  有界で、記録され、どちらでも同一。**対話利用者にとっても退行ではありません** —— 3回失敗して
  記録を残して解放するのは、このリポジトリ自身の規則（同じ問題で2回失敗したらセッションを捨てる）を
  **印字するのをやめて実際に強制する**ことです。

そして掃除役を **cron や launchd にはしませんでした。** ガードレールを解除するのが仕事の
バックグラウンドプロセスは、誰も見ていないときに走る fail-open 機械で、しかも**他人の資格情報を含む
ファイルを編集する `setup.sh` に install/uninstall 経路を増やします。** 掃除は、全ターン終了が既に
歩いている glob の上でやります。規則は1行です: **ある呼び出しがセンチネルを退去させられるのは、
それが今まさに強制しようとしているセンチネルではない場合に限る。**

## 検査が発火していなかった3件 —— どれも「機構ではなく状態」を見ていた

`_shared/` の教訓（下記）は「検査は状態ではなく機構を見なければならない」でした。**同じ間違いが
3箇所で生きていました。**

| 検査 | 何を見ていたか | どう壊れていたか |
|---|---|---|
| `disable-model-invocation` のスコープ照合 | 両側の抽出正規表現が `da-[a-z-]+` にハードコード | **`da-verify` 1件しか比較していなかった。** `x-review-*` の保護は —— `x-` 改名でガードレールが実際に壊れたから足したもの —— 一切比較されず、しかも「両強制者は一致」と緑のチェックを出していた |
| reference のパス形式 | 「相対パスがあり、**かつ本文に `CLAUDE_SKILL_DIR` が一度も出てこない**」 | `x-review-*` 3本は**サブエージェントに絶対形を渡せと指示しながら、表の10パス全部が相対**だった。**正しい書き方に言及しているから通っていた** |
| reference の存在 | 「ファイルがあるのに言及が無い」の一方向だけ | `da-review-all` が `report-format.md` を名指ししていたが、その `reference/` に無かった。**指示に従った人が開くものが無い** |

いずれも**片側を壊して落ちることを確認**してから直しました。落ちない cross-check は、それが防ぐつもりの
ものそのものです。

## `_shared/` は symlink ではなくコピーで、中身がずれていた

README も この文書も「参照セットは symlink で共有している」と書いていましたが、**実際は通常ファイルのコピー**でした。そしてコピーが古く、失われていたのは:

- **`report-format.md` の「レビューに絶対必要な4要件」** —— 変更内容 / テックリードとしての複数観点の批判レビュー（アーキテクチャ・集約・セキュリティを最重視） / 指摘ごとの詳細な理由＋正確な行＋コメント文 / 重要度のレベル分け。**レビュースキル5本すべてに届いていなかった**
- **`finding-discipline.md` の「検証者も偏っている」節** —— 反証既定の根拠。敵対的検証が訂正前のテキストで走っていた
