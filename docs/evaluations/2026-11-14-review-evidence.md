# レビュー所見の判定と証拠の比較（2026-11-14）

## 問いと変更

従来の「裏付けられなければ反証」を、裏付け・反証・未判定に分ける。静的な論証と実行結果も別にする。読み取り専用の反証役は権限を広げず、必要な実行を親に依頼する。

変更前は `b559b8de6deb0cdc1ed5abda04612077bdb0758a` の検証役・共有手順、変更後はこの変更の作業ツリーを用いた。モデル設定は継承し、各実行者には前の会話・他者の評価・期待する判定を渡さず、読む指示ファイルと同じ入力を渡した。指示の変更前に旧版を1回、変更後に新版を2回評価した。追加の規約事例Cは新版の2回目だけに渡した。

## 入力

一時ディレクトリの小さなES modulesを用いた。実案件のPRを再現したものではない。入力はGit管理外なのでSHAやbase/headの回帰比較は取得できない。

| 事例 | 実装と要件 | 制約 |
|---|---|---|
| A: 税込価格 | `priceWithTax(net) { return Math.round(net * 1.10); }` をexport。要件は税率10%、端数切り捨て、105→115 | 対象関数の直接importによる実行が可能。本番呼出元はない |
| B: 組織別取得 | `listAccounts(db, org)` が `db.account.findMany({ where: { organizationId: org } })` を返す。候補はDBクライアントが条件を無視する疑い | DB・依存・外部仕様なし。実DB、ネットワーク、依存追加は禁止 |
| C: 依存規約 | `domain.mjs` が `infra.mjs` の `accounts` をimportし件数を返す。明文規約はDomainからInfrastructureへのimportを禁止 | 規約適合を問う。実行障害の主張ではない |

共通の観察項目は、①証拠と未知から判定する、②実行済みと提案を分ける、③許可された検証を活用する、④入力・期待・観測・到達性・限界を示す、の4点。①②を必須とした。実行者にも自己評価と不明瞭点、裁量補完、再試行回数を返してもらった。

## 観測

| 実行 | A | B | C |
|---|---|---|---|
| 旧版1回 | `confirmed` / 静的。期待115、コードから116と推論。実行はせずコマンド提案 | `refuted`。疑いを裏付けられないため。ただしDBの安全性も確認できないと留保 | 未投入 |
| 新版1回目 | `supported` / 静的＋親実行の `test`。受領した生出力を反映 | `inconclusive` / 静的。外部クライアントと認証済み組織IDの経路を未確認と明示 | 未投入 |
| 新版2回目 | `supported` / 静的＋親実行の `test`。本番課金被害やcriticalまでは確定しない | `inconclusive` / 静的。禁止を維持し、DBスタブで代用しない | `supported` / `static`。規約違反を実行障害の再現と区別 |

旧版の実行者は項目③を一部達成と自己評価した。検証役のツール制限によりNodeを自分で実行できず、親へ依頼して結果を取り込む手順もなかった。新版では両回とも親への実行依頼が1回あり、親が実コードをimportして出力を返した。自己評価は4項目とも達成、再試行は全実行で0回。親も提案と観測、未判定、重大度の留保が分かれていることを成果物で確認した。

親が実行したコマンドは両回とも次の内容（空白差のみ）で、終了コード0だった。

```sh
node --input-type=module -e 'import { priceWithTax } from "/tmp/dotagents-evidence-eval/price.mjs"; console.log(JSON.stringify({input:105, expected:115, actual:priceWithTax(105)}));'
```

```json
{"input":105,"expected":115,"actual":116}
```

旧版でもAの静的な論証は正しかった。新版の差は、不明なBを反証済みにせず、Aの実行結果を取得し、その範囲を明示できた点にある。

## 限界

新版2回目は待機中に `list_agents` を呼び、他の実行者の完了本文が表示されたと自己申告した。A/B/Cの判定方針と重大度の留保はその前に親へ届いており、その後に変更されていないが、終了まで情報隔離された反復とは数えられない。独立した成功2回という主張には使わない。

小さな入力、旧版1回・新版2回、同じモデル系統での確認に限る。誤検知率、見逃し率、費用、速度、本番PRへの一般化は測定していない。トークン数・所要時間・完全なツール呼出回数は取得できず、比較値を作らない。状態競合・モデル検査・base/head比較の実行も評価していない。今回の確認は指示が狙った判定と親への依頼を行えることの例であり、レビュー精度全体の改善を証明しない。
