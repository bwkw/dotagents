# 判断の図と実操作の動画を作る

## 実行条件

| 条件 | 満たさない場合 |
|---|---|
| 求める形式と読み手を依頼・呼び出し元から特定できる | 何を誰に伝えるかを尋ねる |
| ADR 図なら元の ADR、動画なら台本に使う仕様や操作が特定できる | 足りない資料を尋ねる。動画の構成相談は撮影環境がなくても進められる |

## 読むファイル

常に、依頼で指定された元資料と出力先を確認する。その後は該当する形式の手順だけを読む。`${CLAUDE_SKILL_DIR}` を展開しない環境では、この SKILL.md があるディレクトリを起点に解決する。

| 求めるもの | この時だけ読む手順 | 完了の証拠 |
|---|---|---|
| ADR の要約に置く PNG | `${CLAUDE_SKILL_DIR}/figure/guide.md` | 各判断に対応するカードがあり、書き出し時のあふれ検査を通った PNG を開いて確認した |
| 「この操作を動画に」「リリース内容を CS に説明したい」 | `${CLAUDE_SKILL_DIR}/video/guide.md` | MP4 の全シーンで音声・字幕・実際の画面を確認し、撮影で変えた状態を戻した。台本のみの依頼では台本で完了 |

`da-adr` は ADR 本文と PNG の出力先を渡す。図だけの依頼では元の ADR を読み取り専用とする。デモ動画単独の依頼はその依頼文からこのスキルを選び、動画の手順へ進む。生成に必要な依存の確認・導入は形式別の手順に従う。

持ち運べる HTML の構成図が指定された場合は、選択導入の `archify` が利用できればその手順と CLI を使う。使えなければ不足している描画手段と指定形式を伝える。

## 根拠の扱い

判断と理由は元の ADR、操作と説明は実画面・仕様に照合する。確認できなかった箇所を報告し、図や動画に推測を足さない。

## 出力

生成したファイルの場所と実施した検査を返す。外部への配信・公開は宛先と操作の明示指示がある時だけ行う。
