# 一つの設計判断を画像で確かめる

最初に「この図を見た人が、何を選ぶ・確認するか」を一文にする。現状は対象版の実装、提案は仕様または面談の回答、未決は問いに対応付ける。読者が結論まで追える範囲に絞る。

| 判断したいこと | 図に残すもの |
|---|---|
| 誰が状態や処理を持つか | 所有者・保存先の境界を囲み、読み書きの矢印に動詞を付ける |
| どちらの案を採るか | 同じ入力・配置・縮尺で候補を並べ、違う経路とその結果を目立たせる。回答後は採用案を明記する |
| いつ失敗するか | 開始から失敗までの操作順。検査済みの反例は実行結果を使い、仮説には「未確認」と付ける |

**共有する成果物は PNG を基本にする。** 拡大・探索が必要なら、選択導入の `archify` で構成図や状態図の HTML を生成・検査し、同じ図を PNG に書き出す。小さな比較や、書き出しで要点・文字サイズが失われる時は、SVG に判断と実測を直接配置し、既存のブラウザで画像化する。相談中は一時プレビュー、継続して更新する図には編集可能な元資料も残す。画像生成が使えない時は不足を明かし、同じ判断に必要な情報を表で渡す。

表示先の幅で画像を開き、日本語の文字、矢印の向き、境界、文字のあふれを確認する。色に加えてラベルで状態を区別し、画像を読めない人に結論を伝える代替テキストを添える。PR や共有ページは読者が開ける同じ版の画像を指す。外部へのアップロードは依頼された宛先だけに行う。
