# 既存 PR の説明とレビュー依頼を書く

## 実行条件

| 条件 | 満たさない場合 |
|---|---|
| PR の URL、明示されたリポジトリと番号、または本文の依頼なら現在のブランチから対象を一意に特定できる | 不明な対象を尋ねる。複数リポジトリで裸の番号を推測しない |
| 対象 PR の本文・差分・base/head を読める | 読めなかった PR と理由を伝え、読める PR の依頼を続ける |
| GitHub へ書く場合、対象 PR・操作・内容に明示指示がある | 下書きを返す。スキルの起動、番号だけの引数、一覧の依頼は下書きとして扱う |

ソースと設定は読み取り専用。PR 自体をレビューする依頼は `da-review` に渡す。所見の行コメント案やその投稿も `da-review` の手順に従う。

## 読むファイル

常に依頼と対象 PR の URL・タイトル・既存本文を読む。次は目的に合う行だけを読む。`${CLAUDE_SKILL_DIR}` を展開しない環境では、この SKILL.md の場所を使う。

| 目的 | この時だけ読むファイル | 出力・操作 |
|---|---|---|
| 単一 PR のタイトル・本文を書く、既存本文を更新する | `${CLAUDE_SKILL_DIR}/reference/body.md`、`${CLAUDE_SKILL_DIR}/reference/pr-template.md` | 小さい変更は 2〜3 行。構造が変わる時は確認箇所や図を添える。本文だけの更新指示ならタイトルを維持する |
| 1 件以上の PR で Greptile に頼むことを決める、依頼文を投稿する | `${CLAUDE_SKILL_DIR}/reference/greptile.md` | PR ごとに優先度と依頼文を示す。投稿指示があれば指定された PR に各 1 コメント |

## 根拠の扱い

対象 PR 自身の base と head の差分を使い、根拠は該当 head のファイル・行または URL で示す。差分から確認できない検証結果や、未確認の外部サービスの応答はその旨を書く。

## 完了条件

日本語で書いたタイトル・本文・レビュー依頼・利用者への報告は、提示や投稿の前に `ja-writing-humanizer` で推敲する。未導入なら自分で読み直す。指定の書式、動作条件、数値、未確認事項、引用、リンク、メンションを原文と照合する。

下書きなら対象 PR とそのまま使える文面を返す。更新・投稿時は対象 URL を使って結果を読み直し、反映した項目とリンクを返す。投稿の指示は、以降の返信・再依頼や別の PR への投稿には引き継がない。
