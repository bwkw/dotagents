# 図解の定義 —— 要約と要点のカードの書き方と JSON の形

## 要約

図の一番上に置く。ADR を読んでいない人が、ここだけで何を決めたかを掴めるように書く。

- 1〜3 行、各 80 字まで（`summary`）
- 1 行目は「何を決めたか」。図では結論として大きく強調される
- 2 行目以降は、読み手の動きが変わること（使い方・運用・制約）。補足として控えめに描かれる
- 背景・経緯・検討の過程は書かない。理由はカードに任せる

- ✗「家族の取り込みについて検討し、方針を決めた」
- ✓「Porters の本人レコードに並ぶ家族①〜⑧を、Data Connector で家族として取り込む」

## 全体像

データや処理の流れが判断の中心なら置く。左から右へ 2〜4 段（取得 → 変換 → 取り込み など）。

- 箱の名前は ADR と同じにする。`sub` で中身を補う（「`{ person, 家族①〜⑧ }`」など）
- 段の決まりは `note` に一言で書く（「全種類の CSV が揃ってから直列に取り込む」）
- 全体像で見える判断（どこで作るか・どの順か）はカードにしない。カードは流れに出ない判断だけにする

## カードの書き方

カードは要点だけを載せる。1 枚で「何を決め、なぜか」が分かるように書く。残りの理由と対抗案は ADR に任せる。

量の上限（`check` が検査する。`len` は `` ` `` と `**` を除いた字数）：

| 部品 | 上限 |
|---|---|
| `title` | 上限なし。ADR の題をそのまま使う（図と ADR を同じものだと分かるようにする） |
| `summary` | 3 行、各 80 字 |
| カード | 4 枚 |
| カードの見出し | 40 字 |
| 決定、限界、見直す条件などの `text` | 70 字 |
| なぜ | 1 つ（`text` か 1 個の `points`）、70 字 |
| ボツ案 | 1 件。名前 25 字、結果 60 字 |
| 表 | カードに 1 つ、3 行、セル 30 字 |
| 全体像の箱の `sub` | 30 字 |

### 決定

何をするかを、具体例や実際の名前で 1 文にする。抽象語だけで終えない。

- ✗「検索は専用キュー、グループは既存キュー」
- ✓「重い処理の待ち場所がグループには元からあり、検索には無い。検索は長く待てる専用キューで待つ」

### なぜ

**一番強い理由を 1 つだけ、仕組みまで書く。** 「〜が違うため」「〜を優先した」で止めない。何をすると、どこで困るから、こうする、まで続ける。

- ✗「混雑時の待ち時間が異なるため」
- ✓「グループは待ち行列に 1 行書けば終われるが、検索は実行枠が埋まると断られ、キューで待つしかない」

### ボツ案

読み手が真っ先に思いつく対抗案が 1 つあるときだけ置く。名前（`name`）と「その案だと何が起きるか」（`result`）を書く。

- ✗「複雑になる」
- ✓「CSV 取込や一括更新で、通知を書き忘れる」

数値は ADR か、ADR が引くコード・実測にあるものだけを使う。出典の無い数値は載せない。

### 表

2 つ以上の選択肢を同じ観点で比べる方が文より速いときだけ、表（`table`）にする。行が選択肢、列が観点。表は「決定」の後、「なぜ」の前に置く。
表と同じことを決定やなぜで繰り返さない。全体像に描いた一覧をカードの表で描き直さない。

### 見直す条件・限界・例・ポイント

任意。要点の理解に欠かせない時だけ 1 つ置く。

### 名前

ADR と同じ名前を使う。同じものを図と ADR で別の名前にしない（「イベント記録」と「変更記録」など）。字数を詰めるために略さない（「Highly Confidential」を「Highly」にしない）。収まらなければ、名前ではなく文の中身を削る。識別子は `` `バッククォート` `` で囲む。

## JSON の形

見本は `example.json`。必須でないものは省いてよい。

```jsonc
{
  "title": "図のタイトル（ADR の結論）",
  "width": 1600,                       // 省略時 1600。高さは中身で決まる
  "summary": ["何を決めたか：**強調** と `code` が使える", "読み手の動きが変わること"],  // 必須。1〜3 行
  "overview": {                        // 任意
    "title": "アーキテクチャ全体像",
    "stages": [                         // 左から右へ。2〜4 段
      {
        "title": "段の見出し",
        "dashed": true,                 // 同じ Transaction などの囲み
        "down": false,                  // true なら rows を ↓ でつなぐ
        "rows": [                       // 各行は → でつなぐ
          [
            { "name": "Repository", "sub": "補足" },
            [{ "name": "表 A", "kind": "store" }, { "name": "表 B", "kind": "store" }]  // 配列は縦に積む
          ]
        ],
        "note": "段の下の注記"
      }
    ],
    "aside": { "label": "配信を使わないもの", "text": "全体像の下の注記" }
  },
  "cards": [                           // 4 枚まで
    {
      "title": "判断の見出し（ADR の節の主張文）",
      "parts": [
        { "tag": "決定", "text": "…" },
        { "table": { "head": ["", "観点 1", "観点 2"], "rows": [["案 A", "…", "…"]] } },
        { "tag": "なぜ", "text": "…" },
        { "tag": "ボツ案", "alternatives": [{ "name": "…", "result": "…" }] },
        { "tag": "見直す条件", "text": "…" }
      ]
    }
  ]
}
```

- `tag` に使えるのは `決定`・`なぜ`・`例`・`ボツ案`・`見直す条件`・`限界`・`ポイント`
- 箱の `kind` は `store`（表・記録）と `queue`（キュー・トピック）。省くと普通の箱
- 文字列はすべてエスケープされ、`` `code` `` と `**強調**` だけが書式になる。HTML は書けない
