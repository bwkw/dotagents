# 図解の定義 —— カードの書き方と JSON の形

## カードの書き方

図は、ADR を読む前の人が見る。カード 1 枚で「何を決め、一番強い理由は何で、一番強い対抗案だと何が起きるか」が分かるように書く。残りの理由と対抗案は ADR に任せる。

量の上限（`check` が検査する。`len` は `` ` `` と `**` を除いた字数）：

| 部品 | 上限 |
|---|---|
| `title` | 上限なし。ADR の題をそのまま使う（図と ADR を同じものだと分かるようにする） |
| `lead` | 1 行、80 字 |
| カードの見出し | 55 字 |
| 決定、限界、見直す条件などの `text` | 90 字 |
| なぜの `points` | 2 個、各 70 字 |
| ボツ案 | 2 件。名前 25 字、結果 60 字 |
| 表 | カードに 1 つ、4 行、セル 30 字 |
| 全体像の箱の `sub` | 30 字 |

### 決定

何をするかを、具体例や実際の名前で書く。抽象語だけで終えない。

- ✗「検索は専用キュー、グループは既存キュー」
- ✓「重い処理を待たせておく場所が、グループには元からあり、検索には無い。検索はキューそのもので待つので、長く待てる専用キューを作る」

### なぜ

**仕組みまで書く。** 「〜が違うため」「〜を優先した」「今は要求が無い」で止めない。何をして、どこで失敗し、その失敗が何を意味するから、こうする、まで続ける。

- ✗「混雑時の待ち時間が異なるため」
- ✓「グループは待ち行列に 1 行書けば受信を終えられるが、検索は実行枠が埋まると登録を断られ、キューで待つしかない」

理由は箇条書き（`points`）で 1〜2 個。いちばん強い理由を先に置く。

### ボツ案

案ごとに、名前（`name`）と「その案だと何が起きるか」（`result`）を書く。

- ✗「複雑になる」
- ✓「CSV 取込や一括更新で、通知を書き忘れる」

数値は ADR か、ADR が引くコード・実測にあるものだけを使う。数値があると反論が出にくいが、出典の無い数値は載せない。

### 表

2 つ以上の選択肢を同じ観点で比べる判断は、表（`table`）にする。行が選択肢、列が観点（「何をするか」「失敗の意味」「だからどうするか」）。表は「決定」の後、「なぜ」の前に置く。
表は文章の代わりに使う。表と同じことを決定やなぜで繰り返さない。全体像に描いた一覧をカードの表で描き直さない。

### 見直す条件・限界・例・ポイント

- ボツ案の無い判断には「見直す条件」か「限界」を置く
- 抽象的な決定には「例」で具体的な値の流れを 1 つ見せる（「職位を改名 → `JOB_TITLE`・`[NAME]` → 検索だけが作り直す」）

### 名前

ADR と同じ名前を使う。同じものを図と ADR で別の名前にしない（「イベント記録」と「変更記録」など）。字数を詰めるために略さない（「Highly Confidential」を「Highly」にしない）。収まらなければ、名前ではなく文の中身を削る。識別子は `` `バッククォート` `` で囲む。

## JSON の形

見本は `example.json`。必須でないものは省いてよい。

```jsonc
{
  "title": "図のタイトル（ADR の結論）",
  "width": 1600,                       // 省略時 1600。高さは中身で決まる
  "lead": ["基本方針：**強調** と `code` が使える"],
  "overview": {
    "title": "アーキテクチャ全体像",
    "stages": [                         // 左から右へ。2〜4 段
      {
        "title": "段の見出し",
        "dashed": true,                 // 同じ Transaction などの囲み
        "down": false,                  // true なら rows を ↓ でつなぐ
        "rows": [                       // 各行は → でつなぐ
          [
            { "name": "Repository", "sub": "補足" },
            [{ "name": "表 A", "kind": "store" }, { "name": "表 B", "kind": "store" }]  // 配列は縦に積む
          ]
        ],
        "note": "段の下の注記"
      }
    ],
    "aside": { "label": "配信を使わないもの", "text": "全体像の下の注記" }
  },
  "cards": [
    {
      "title": "判断の見出し（ADR の節の主張文）",
      "parts": [
        { "tag": "決定", "text": "…" },
        { "table": { "head": ["", "観点 1", "観点 2"], "rows": [["案 A", "…", "…"]] } },
        { "tag": "なぜ", "points": ["…", "…"] },
        { "tag": "ボツ案", "alternatives": [{ "name": "…", "result": "…" }] },
        { "tag": "見直す条件", "text": "…" }
      ]
    }
  ]
}
```

- `tag` に使えるのは `決定`・`なぜ`・`例`・`ボツ案`・`見直す条件`・`限界`・`ポイント`
- 箱の `kind` は `store`（表・記録）と `queue`（キュー・トピック）。省くと普通の箱
- 文字列はすべてエスケープされ、`` `code` `` と `**強調**` だけが書式になる。HTML は書けない
