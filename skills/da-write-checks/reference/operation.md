# 実操作の検査と更新

通常の利用者と同じ入口から、意味のある操作を1件選ぶ。操作後の保存内容・表示・終了コードなど、成功の主張を覆せる観測を選ぶ。制御用のCLI、ブラウザ、サービスの順に優劣を決めず、その条件を実際に観測できる入口を使う。

| 残すもの | 内容 |
|---|---|
| 起動と準備 | 既存の起動コマンド、隔離した保存先、既知の初期状態、用意すべき権限 |
| 操作と観測 | 機能ごとの操作、期待、取得した結果、再実行コマンド。失敗時に読めるログや画像を置く |
| 復元 | 自分が起動したプロセスと一時データを片付け、証拠が残っていることを確認 |
| 更新時の判断 | 対応表と現行の画面・コマンド・実装の差分を確認。仕様が同じで実装が失敗すれば回帰。仕様変更に手順が追従していなければ手順の更新。認証や依存の不足なら未確認 |

検査自身の試験では、隔離した対象で保存の欠落など利用者に現れる故障を入れ、先に決めた期待値のまま実行する。アプリ起動の失敗だけを観測して、保存の故障を検出したとは報告しない。複数機能を扱う手順は、機能・対応する実装・再実行する検査を1行ずつ対応付け、次の担当者が手順書だけで再実行できることを確かめる。
