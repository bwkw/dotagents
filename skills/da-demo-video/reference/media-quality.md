# 完成動画の音声・ズーム・撮影品質

## 音声は完成MP4から検証する

`compose` はナレーションのPCM音声と映像を独立して生成し、最後に結合する。以前の同時書き出しでは、元WAVが正常でも、完成MP4の約34秒以降に音声が欠落した。コンテナの表示尺とデコード成功だけでは分からず、取り出した音声の実サンプル長も映像より長くなっていた。

結合後は、完成MP4をPCMへ戻して尺を比較し、各シーンの開始位置で元WAVとの波形・音量を照合する。`audio-verification.json` の `ok: true` と全シーンの結果を確認する。検査に失敗した時は非0で終了し、以前の成功レポートも失敗結果に置き換わる。

動画を別のツールで編集・再結合した時も、配布するファイルを `output` に指定して再検証する。

```bash
node ${CLAUDE_SKILL_DIR}/scripts/demo.mjs verify <作業ディレクトリ>/scenario.mjs
```

音声ファイルを生成し直したら、検証対象の動画も再結合する。検証が保証するのは音声の配置と欠落・音量であり、読み方、声の聞こえ方、話す内容と操作の意味の一致は含まない。聞いていなければ「配置・欠落は機械検証済み、読み方・聞こえ方は未確認」と報告する。

## ズーム途中も見る

`h.hl(locator)` は対象の表示位置へ毎フレーム追従する。固定座標の `h.hl(rect)` は、その座標を囲み続けるので、動く対象にはlocatorを渡す。ズーム中は結果を見せ、次の操作前に `h.unzoom()` で戻す。

`record` はズーム途中・拡大後・解除途中・解除後を `stills/zoom-*.jpg` に保存する。各シーンの35%・85%だけでは、短いズーム演出のずれを見逃すため、両方を見る。

- 対象全体を枠が囲み、拡大中も枠だけ古い位置に残らないか
- 対象の文字や関連項目が画面外へ切れていないか
- 枠やテロップが、読むべき情報を隠していないか
- 解除後に元の位置へ戻り、次の操作前に枠が消えているか

問題があれば `timeline.json` の時刻で完成MP4から静止画を切り出す。冒頭カードも、縮小した一覧だけでなく元の大きさで3行の文字が読めるか確認する。

## 撮影で踏んだ落とし穴

- **初回表示が 30 秒を超える環境がある。** `ready` の待ちは 120 秒にしてある
- **撮る側のページの CSS が演出に効く**（`div { ... }` でカードが半透明になった）。演出は Shadow DOM に閉じ込めてある
- **CSP で inline script が弾かれる。** コンテキストを `bypassCSP: true` で開いている
- **ページが動くクリックの後、枠が古い位置に残る。** `clickAndClear` を使う
- **スクロールの直後に枠を描くと、位置がずれる。** `scrollTo` がスクロールの停止を待つのはこのため
- **ズーム中はドロップダウンの位置がずれる。** ズームは見せるだけの場面に使い、操作の前に `unzoom`
- **並べ替えた要素は、locator の index が変わる。** 入力した値など、中身で探し直す
- **ログイン状態を持続的な場所へ写す操作は、権限の判定で止められる。** `auth.json` は作業ディレクトリにだけ置き、必要ならもう一度 `login` してもらう
