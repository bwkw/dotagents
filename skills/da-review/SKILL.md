# /da-review — 設計と差分の所見を返す

**レビューは読み取り専用。** コード・設定・設計書を変更しない。成果物は所見と、対象と持ち主に応じた概要・行コメントの下書き。投稿は下書きへの明示の指示があった時だけ行う。

## 実行条件

| 条件 | 満たさない時 |
|---|---|
| 設計を頼まれた時は対象の仕様・計画が特定できる | `spec_system` から解決し、なお不明なら対象を尋ねる |
| 差分を頼まれた時は PR、ローカル差分、指定パスの範囲を確定できる | 引数なしのコードレビューは作業中の差分から始める。空なら変更なし、取得に失敗したら理由を伝える |
| 他人の PR と自分の作業を区別できる | 共有ブランチ等で曖昧な時は持ち主を尋ねる |

## 読むファイル

常に依頼と対象を読む。`${CLAUDE_SKILL_DIR}` はこのスキルのディレクトリ。変数を展開しないホストではこのファイルの親から解決し、対象に対応する手順だけを開く。

- **設計**は `${CLAUDE_SKILL_DIR}/reference/design.md`。仕様の規約は `${CLAUDE_SKILL_DIR}/reference/spec-system.md` に従い、`spec_system` の validator と禁止コマンドを照合する。コードを開いて裏付ける予算は25ファイル。不可逆になる瞬間と移行順を示し、必ず **🧱 Landing plan** に着地ごとの **What gates it** を含める。並行や再試行など操作順が争点なら一時モデルを調べ、反例・探索上限・実装での観測を所見に添える。
- **差分・PR** は `${CLAUDE_SKILL_DIR}/reference/diff.md`。意図、対象 head、担当する層を確定する。範囲が **1,000 行以下**なら各 `x-review-<layer>` を同じ文脈で呼び「**inline, no subagents**」と記録する。1,000 行超、または PR ごと・所見ごとの検証を頼まれた時は **fan-out**。担当ごとにレビュー役、所見ごとに `x-review-verifier` を使い、モデルは継承する。サブエージェントの無いホストでは同じ文脈で進め、届いた範囲を示す。
- **設計と差分の両方**を指定されたら両方の手順を使う。設計の約束・着地の条件ごとに、実装側の該当箇所と確認結果を対応づける。所見の重複はまとめ、設計では想定できても現時点の実装で確かめられなかった点を明記する。

## 根拠の扱いと完了条件

各所見に、対象の `path/file:L42`、影響、反証の結果を添える。実行して観測した結果、静的な裏付け、未判定を区別する。外部の主張には一次資料の URL を付ける。選んだ経路の完了条件を満たし、未確認の範囲を返す。

他人の PR では概要ページとユーザーの口調のコメント下書きを返す。投稿を頼まれたら対象の PR・head・行を照合し、指示された範囲だけ投稿する。承認・変更要求にはその状態を指定する本人の指示が要る。
