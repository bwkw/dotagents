# ADR の型 —— 判断の記録として書く

`final-design.md` が「誰に向けて書くか」を決め、このファイルが「どういう形で書くか」を決める。
**リポジトリに既存の ADR があり、この型と食い違うなら、最も新しい既存 ADR の形が勝つ。**

ADR は決定の羅列ではない。**「なぜこうなっているのか」と聞いた新規参加者が、読んで自分で判断できる**
ための記録である。規範（何をすべきか）はコードとスキーマコメントにあり、ADR は判断（なぜそれを選び、
何を諦めたか）を持つ。

---

## 構成

上から順に置く。**★は必須**。それ以外は判断の性質に応じて置き、置かないなら理由がある。

| 節 | 中身 |
|---|---|
| ★ `# ADR: <結論を 1 文で>` | タイトルが結論そのもの。「〜は〜で表し、〜する」。トピック名（「〜の設計」）にしない |
| ★ `## 状態` | 「採用。」＋対象範囲（何を扱い、何を扱わないか）。隣の ADR やスキーマコメントが正典の部分は、そちらへリンクして「本 ADR は〜を選ぶ理由を扱う」と線を引く |
| ★ `## この ADR が答える問い` | 番号付き。各問いの末尾に `（§N）`。読み手が実際に口にする形の問いにする |
| ★ `## 先に結論の要約` | 箇条書き。**問いと 1 対 1**、各行末に `（§N）`。ここだけ読めば判断が分かる |
| `---` | 要約と本文の区切り |
| `## 0. 前提` | 業務上の事実・用語・現状。**出どころを書く**（誰に確認したか、どの一次情報か）。判断がこの事実に依っていることを明示する |
| ★ `## 1.` 〜 `## N.` 判断 | 見出しは**主張文**（「承認プロセスを置かない」「集約境界は利用者単位」）。1 節 1 判断。本文は「何をするか → なぜか」 |
| `## 却下した代替案` | `### 案 A: 〜` の形。各案に負ける理由。判断の節自体が「X を置かない」形で却下を内包しているなら、独立節は不要 |
| `## 失っているもの（評価つき）` | 選んだ形で**できなくなること**を、影響の大きさの評価つきで。どれが最も効くかの順位も書く |
| `## 想定される疑問` | 見出しを `### 「〜ではないか」` と読み手の声で書き、答える |
| `## いつ考え直すか` | `### 引き金`（何が起きたら）と `### 先にやるべき、安いほうの手` |
| `## 関連ドキュメント` | spec、隣接 ADR、外部の正典 |

### 判断の節の中に置くサブ見出し

必要に応じて `###` で添える。

- **上限** —— `### 上限: 〜` として、この判断が成り立たなくなる条件や、集約に載りうる例外を独立に書く
- **命名** —— 名前が一般的な語と違う意味で使われているなら、その理由を書く。同じ語を 2 つの問いに名乗らせない
- **読んでよい場面** —— 判断の例外が正しく使われる場面を列挙する

## 書き方

1. **読んで動ける言葉で書く。** 制約は「表現できない」で止めず、**何ができず、何は答えられるか**まで書く。
   ✗「履歴が交差するケースは表現できない」 ✓「答えられないのは再登録の回数と、どの登録が失効したかである。その日に有効かどうかは答えられる」
2. **将来の変更は、触る場所を数で書く。** ✗「キーを広げる必要がある」 ✓「広げる日に触るのは、この値を読む 4 箇所」。
   触らなくてよいもの（既存データの移行が要らない、等）も同じ段落で言い切る
3. **見出しが誤りを前提にしない。** ✗「分け方を誤っても戻せる」 ✓「分け方は、既存のデータを書き換えずに変えられる」。
   性質として述べる
4. **測っていないことを「小さい」「低い」と言い換えない。** 評価には根拠（件数・証言・一次情報）を添えるか、未測定と書く
5. **外部出典は論拠に使う箇所へインラインで貼る。** 末尾の参考文献に寄せない
6. **表は N×M の対応にだけ使う**（「答えるもの × 書き手」など）。1 次元の列挙は箇条書き
7. **太字は「ここだけは通したい 1 文」に絞る。** 句読点の直後に `**` を置かない（`SKILL.md` Step 5）
8. **記号は順に振る。** 却下案が「F-2 → F」のように並ぶと、後から差し込んだ跡が見える。書き直すたびに振り直す

## 既存 ADR を更新するとき

- **コードから参照されている §番号・見出しアンカーを壊さない。** 更新前に ADR のファイル名と `§` でコードを検索し、
  番号を変えるなら参照側も直す
- **変遷を足さない。** 「当初は〜だったが」を追記するのではなく、現在の理解で該当節を書き直す
  （`final-design.md`：書き直しの指示であって編集の指示ではない）。2 か所以上で経緯が混ざるなら全体を書き直す
- 前の判断を覆すなら、覆したことは書かずに新しい判断を書き、旧案は却下案に**選ばない理由**として置く

## 書き終えたら

- [ ] タイトルだけで結論が分かる
- [ ] 問い・要約・本文の §番号が 1 対 1 で揃っている
- [ ] 前提の事実に出どころがある
- [ ] 「何ができなくなるか」が、読んだ人が判断できる具体さで書かれている
- [ ] 評価の語（小さい・十分・低い）すべてに根拠か「未測定」がある
