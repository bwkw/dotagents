# 口調プロファイル —— 例

> ⚠️ **このファイルをその場で編集しない。** `.gitignore` は `profiles/*.md` を無視するが **`_example.*.md` は
> 許可しているので、このファイルは追跡されている**。ここに書いたものはコミットされ push される。最後の節は
> 実際に書いたコメントを求めるが、多くの人にとってそれは勤務先のコードである。
> **先にコピーしてから書く:** `cp profiles/_example.review-voice.md profiles/review-voice.md`

コピーを、**自分が**実際に書く形に書き直す。`profiles/review-voice.md` は追跡されない。

`pr-comments.md` は下書きの前にこれを読み、無ければ**口調を作らずに質問する**。自分が使わない口調のコメントが
自分の名前で投稿されると自分の発言として読まれ、取り消せないため。どう書くべきかではなく、実際に書いた
コメントから埋める。

下の軸は出力を変えるものだけ。関係ない軸は消す。短くて正直なファイルの方が、揃っているが作り物のファイルより良い。

## 言語

日本語 / 英語 / 日本語で技術用語は英語のまま、のどれか。リポジトリや読み手で変わるならそれも書く。

## 口調

- **断定か質問か。** 「これは N+1 になる」か「ここ N+1 になりませんか？」か。多くの人は一定でないので、何で決まるかを書く（重大度？ 確信の有無？ 相手が先輩か？）
- **直接さ。** 指摘が先か、文脈が先か
- **ぼかし。** 実際に使うぼかし表現と、書くと謙遜に見えすぎるもの
- **長さ。** 1 コメント 1〜2 文か、理由を全部書くか

## 守っている決まり

記録するものの例（自分のものに置き換える）:

- nit の印の付け方（`Nit:` / `[nit]` / 「些細ですが」）と、まとめるか個別にするか
- 直し方まで書くか、問題だけ書くか
- 読んだものに `file:line` を付けるか、コメント対象にだけ付けるか
- やらないこと（絵文字？ 褒めの前置き？「一応」？）

```
（実際に書いたコメントをそのまま貼る）
```
